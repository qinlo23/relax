# Kite 前端架构说明

项目使用 pnpm workspace，包含两个可独立构建的 Vue 应用和三个共享源码包。
完整启动、验证和部署命令见 [前端说明](../README.md)。

## 应用层

- apps/web：前台门户、个人中心、博客、图库、价格、AI 和冥想模块。
- apps/admin：管理后台，独立登录页，部署在 /admin/。
- 两个应用分别维护入口、路由、Pinia、Vite 和页面布局；每个应用内部采用 core/modules/shared/layouts 分层。
- @/ 别名只在所属应用中使用。应用不互相导入，两个应用不提供固定互跳入口，登录和退出流程仅在各自应用内完成。

## 共享层

- @kite/contracts：共享接口、DTO、VO 与通用类型，不依赖浏览器或业务应用。
- @kite/platform：HTTP、结构化错误、token 存储、认证接口、服务端权限同步、权限指令、公共内容读取。
- @kite/ui：登录表单、全局样式与主题、共用图片资源。表单认证成功后发出事件，不决定应用跳转。
- 依赖方向：应用 → ui/platform/contracts；ui → platform/contracts；platform → contracts。
- 公共包通过 exports 和 workspace:* 引用，由 Vite 直接编译源码；Vue 等运行时通过 peer dependency 由应用提供。

## 认证与路由

前台 / 和后台 /admin/ 可同源或分别部署，构建时通过 __KITE_APP_ID__ 固定应用身份，独立保存 token、用户缓存和主题。
web 使用 kite_front_*，admin 使用 kite_admin_*；存储命名不依赖域名、端口或当前路径。
每个应用通过 /user/info 取得真实权限，缓存不授予权限。同一应用跨标签页通过 storage 事件同步登出与主题；不同应用互不影响。
后台路由内部不重复 /admin 前缀，Vite 与 Router base 均为 /admin/。
后台独立登录页保留并校验返回地址，无后台权限进入无权限页。

## 工程与部署

根目录集中维护锁文件与开发脚本；apps/* 和 packages/* 是 workspace 成员。
开发、预览统一入口分别为 5173、5179；后台内部端口分别为 5174、5180。
构建分别输出 dist/web 和 dist/admin，清理范围限定各自产物目录。
Nginx 分别提供两个应用的 HTML 回退，/api 继续转发现有后端。
